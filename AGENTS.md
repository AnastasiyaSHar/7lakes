# AGENTS.md — правила работы над лендингом «Семь Озёр · Монстры»


Этот файл описывает, как агенты (люди и ИИ) должны работать над проектом.
Читайте его перед любыми изменениями. Если правило противоречит задаче —
сначала обсудите, потом меняйте.

---

## 1. О проекте

- **Что это:** одностраничный лендинг новогодних каникул в стиле «монстры»
  для загородного комплекса «Семь Озёр» (85 км от Санкт-Петербурга).
- **Цель страницы:** получить заявку на бронирование / запись на мастер-класс.
- **Аудитория:** родители 30–45 лет с детьми 4–12 лет, преимущественно мамы.
- **Тон:** дружелюбный, с лёгкой иронией, без сюсюканья и без канцелярита.
- **Язык интерфейса и контента:** русский.

## 2. Технический стек и структура

- Статический лендинг: **HTML + CSS + vanilla JS**, без сборщиков и фреймворков.
- Всё в одном файле `index.html` (стили в `<style>`, скрипты в `<script>` в конце).
- Внешние библиотеки и CDN **не подключать** без явного согласования.
- Шрифты — системные (`Segoe UI`, `system-ui`, `Roboto`, sans-serif).
  Подключение веб-шрифтов — только по согласованию.
- Изображения (если появятся) хранить в `assets/`, подключать относительными путями.

```
/
├── AGENTS.md
├── index.html
└── assets/          # изображения, иконки (если нужны)
```

## 3. Дизайн-система

Все цвета, радиусы и тени брать **только из CSS-переменных** в `:root`.
Не хардкодить цвета в правилах — использовать `var(--...)`.

| Токен | Значение | Назначение |
|---|---|---|
| `--bg` | `#f6f4fb` | светлый фон страницы |
| `--ink` | `#1c1230` | основной текст |
| `--ink-soft` | `#4a3f63` | вторичный текст |
| `--violet` | `#6b3fd4` | основной акцент |
| `--violet-deep` | `#4a1fa8` | тёмный акцент, градиенты |
| `--lime` | `#c6f24e` | CTA-кнопки, акценты |
| `--lime-deep` | `#a8d92e` | hover CTA |
| `--teal` | `#2fd6c3` | дополнительный акцент |
| `--radius` | `26px` | скругление карточек |

Правила стиля:
- Светлый фон, **стеклянные карточки** (`.glass-card`): полупрозрачный белый
  фон + `backdrop-filter: blur(...)` + светлая рамка + мягкая тень.
- Крупные акцентные кнопки (`.btn`) — градиент лайм → лайм-дип, скругление 60px.
- Плавные анимации: появление блоков через класс `.reveal` + `.visible`,
  hover-подъём карточек (`translateY(-8px)`), parallax на первом экране.
- Не добавлять новые «тяжёлые» эффекты (3D, шейдеры, видео-фоны) без согласования.

## 4. Правила вёрстки

- Семантические теги: `header`, `section`, `footer`, `nav`, `button`.
- Заголовки — по иерархии: один `h1` на страницу, далее `h2`, `h3`.
- Все интерактивные элементы — `button` или `a` (не `div` с `onclick`).
- Вёрстка адаптивная: брейкпоинты **960px** и **640px** (см. медиазапросы).
- Мобильная версия обязательна: кнопки на мобильных — на всю ширину.
- Не использовать `!important` без крайней необходимости.

## 5. JavaScript

- Только vanilla JS, без jQuery и полифилов.
- Скрипты — в конце `<body>`, в одном блоке `<script>`.
- Анимации появления — через `IntersectionObserver` (класс `.reveal` → `.visible`).
- Обработчики скролла — с `{ passive: true }`.
- Уважать `prefers-reduced-motion`: при reduced motion отключать анимации
  (соответствующий медиазапрос уже есть — не удалять его).
- Не добавлять глобальные переменные; всё в IIFE или локальных `const`.

## 6. Контент и копирайтинг

- Тон и формулировки **не менять произвольно** — тексты согласованы с заказчиком.
- H1, блок болей, блок решений и текст кнопки — **зафиксированы**:
  - H1: «7 дней без “мам, мне скучно”. Новогодняя монстр-программа в “Семи Озёрах”».
  - Кнопка: **«Хочу к монстрам»** (во всех CTA-местах).
- Факты о комплексе (32 га, 85 км, коттеджи, ресторан, зоопарк, детский клуб,
  аниматоры 4–12 лет) — не выдумывать новые, не удалять существующие.
- Цены мастер-классов (800 ₽), дедлайн акции (до 15 декабря) — менять только
  по явному указанию заказчика.
- Микротекст под кнопками (согласие на обработку данных) — обязателен,
  не удалять и не сокращать до потери смысла.

## 7. Доступность (a11y)

- У всех кнопок и ссылок — понятный текст (не «нажмите здесь»).
- Контраст текста к фону — не ниже WCAG AA.
- FAQ-аккордеон: кнопки должны быть фокусируемы с клавиатуры (`button`),
  состояние `open` — визуально различимо.
- Изображения — с `alt` (если появятся).
- Не отключать фокус-обводку у интерактивных элементов.

## 8. Производительность

- Не подключать тяжёлые библиотеки ради одной функции.
- CSS-анимации — только `transform` и `opacity` (не `top/left/width`).
- `backdrop-filter` использовать умеренно (только на карточках и хедере).
- Изображения — сжатые, в WebP, с `width`/`height` для предотвращения сдвигов.

## 9. Процесс изменений

1. Прочитайте этот файл и раздел, которого касается задача.
2. Вносите **минимальные** изменения: не переписывайте работающие блоки
   без необходимости.
3. Не удаляйте существующие токены, классы и обработчики без согласования.
4. Проверьте результат в браузере на десктопе и в мобильном виде
   (DevTools → режим устройства, ширина 375px и 768px).
5. Проверьте, что анимации появления срабатывают и FAQ открывается.
6. Если меняли контент — сверьтесь с разделом 6.

## 10. Чего делать нельзя

- Менять H1 и текст CTA-кнопки без согласования.
- Добавлять фреймворки, сборщики, CDN-библиотеки.
- Хардкодить цвета вместо CSS-переменных.
- Удалять микротекст согласия под кнопками.
- Убирать медиазапрос `prefers-reduced-motion`.
- Ломать адаптивность (проверять на 375px и 768px).
- Добавлять скрытые поля, трекеры и сторонние скрипты без согласования.

## 11. Деплой

Проект статический, поэтому подходит любой хостинг статики.
Рекомендуемый порядок — от простого к сложному.

### 11.1. Быстрый предпросмотр (локально)
- Открыть `index.html` двойным кликом в браузере.
- Для проверки относительных путей — запустить локальный сервер:
  `python3 -m http.server 8080` в корне проекта, открыть `http://localhost:8080`.
- Не коммитить локальные серверные файлы и временные артефакты.

### 11.2. GitHub Pages (основной вариант)
- Репозиторий: один, ветка `main`.
- В настройках репозитория: **Settings → Pages → Source: Deploy from a branch**,
  ветка `main`, папка `/ (root)`.
- Сайт доступен по адресу `https://<username>.github.io/<repo>/`.
- В корне должен лежать `index.html` — иначе Pages отдаст 404.
- Файл `.nojekyll` добавить в корень, чтобы GitHub не обрабатывал файлы через Jekyll.

### 11.3. Netlify / Vercel (альтернатива)
- Подключить репозиторий, build command — пустой, publish directory — `/`.
- Автодеплой при пуше в `main`.
- Проверить, что превью-ссылки не индексируются (для черновиков — `noindex`).

### 11.4. Требования к деплою
- Перед публикацией: проверить страницу на 375px и 768px, убедиться, что
  анимации и FAQ работают, нет битых ссылок и пустых `href="#"`.
- Не деплоить с закомментированным кодом и `console.log` в продакшн-версии.
- Не хранить в репозитории секреты, токены и ключи API.
- Кэш: статику отдавать с длинным `Cache-Control`, `index.html` — без кэша
  (или с коротким), чтобы правки контента применялись сразу.

## 12. Соглашения по коммитам

Формат сообщения — **Conventional Commits**, на русском или английском
(выбрать один язык и придерживаться его во всём репозитории).

```
<тип>(<область>): <краткое описание>
```

Типы:
- `feat` — новая функциональность (блок, форма, анимация);
- `fix` — исправление бага (вёрстка, скрипт, ссылка);
- `style` — только оформление (отступы, цвета, форматирование), без логики;
- `content` — правки текстов, цен, расписания;
- `refactor` — переработка кода без изменения поведения;
- `perf` — оптимизация производительности;
- `docs` — документация (включая этот `AGENTS.md`);
- `chore` — служебные изменения (конфиги, `.gitignore`).

Области (scope): `hero`, `pain`, `solution`, `schedule`, `master`, `trust`,
`cta`, `faq`, `final`, `footer`, `a11y`, `deploy`.

Примеры:
```
feat(cta): add booking form stub with phone field
fix(faq): restore accordion toggle on mobile
content(schedule): update day 3 masterclass time
style(glass-card): soften border and shadow
docs(agents): add deploy and commit conventions
```

Правила:
- Один коммит — одно логическое изменение.
- Заголовок — до 72 символов, в повелительном наклонении.
- В теле (при необходимости) — **что** и **почему**, а не «как».
- Не коммитить сгенерированные файлы, `.DS_Store`, `node_modules`, временные папки.
- Ветки: `main` — стабильная; фичи — `feat/<кратко>`, фиксы — `fix/<кратко>`.
- Перед пушем в `main` — проверить страницу в браузере (см. раздел 9).
